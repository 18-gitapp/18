# Linux Runner

یک لینوکس (Ubuntu) روی GitHub Actions که مدتی که تو تعیین می‌کنی زنده می‌مونه. هر چیزی که روش اتفاق بیفته، **فقط با فایل‌هایی که خودت توی پوشه‌ها می‌ذاری** تعریف میشه.
بدون هیچ فایلی: یک لینوکس خام بالا میاد، `RUN_MINUTES` دقیقه صبر می‌کنه و تموم میشه. تنها سکرت لازم: `RUN_MINUTES`.

```
linux/            ← دستورهای خود لینوکس (مثل SSH)           ← کاربر runner با sudo بدون رمز (= root)
  start/          اول شیفت، یکی‌یکی (نصب، تنظیم، ریستور)
  services/       سرویس‌های دائمی (کرش کنه ری‌استارت میشه)
  end/            آخر شیفت، سرویس‌ها هنوز روشن
  final/          آخر شیفت، بعد از خاموشی سرویس‌ها (بکاپ)
github/           ← دستورهای رانر گیت‌هاب (مثل مراحل yml)    ← هر پوشه یک step جدا
  pre/            قبل از فاز لینوکس
  post/           بعد از فاز لینوکس (تحویل به اکانت بعدی)
  always/         همیشه، حتی اگه چیزی خراب بشه
handoff/  next-repo/   ← مخصوص ماژول تحویل (پایین)
runner/           ← موتور؛ دست نزن
backup.paths  backup.exclude  overlay.roots  overlay.exclude   ← تنظیمات بکاپ
```
قانون: هر پوشه فقط `*.sh`ها رو به **ترتیب نام** اجرا می‌کنه. `*.example` و بقیه نادیده گرفته میشن. فایل رو حذف کنی = قابلیت خاموش.

## ماژول‌های آماده (هر کدوم یک یا چند فایل؛ برای خاموش کردن فایل رو حذف کن)

| ماژول | فایل‌ها | کار |
|---|---|---|
| بکاپ و ریستور | `linux/start/00-baseline.sh`، `10-restore.sh`، `linux/final/50-backup.sh` | حالت ماشین (پکیج‌های apt + فایل‌های تغییرکرده + `backup.paths`) در تکه‌های ۴۰MB ذخیره و اول شیفت بعد برمی‌گرده |
| تحویل | `github/post/10-handoff.sh`، `linux/start/05-handoff-set.sh` | بکاپ + ریپو به `NEXT_REPO` (یا همین ریپو) میره، سکرت‌ها منتقل میشن، workflow بعدی شروع میشه. **حذفش = شیفت تموم میشه و تمام** |
| Tailscale | `linux/start/30-tailscale.sh`، `linux/final/90-tailscale-logout.sh` | اتصال به tailnet، SSH بدون رمز: `ssh runner@<ip>` |
| دسکتاپ + VNC | `linux/start/40-desktop.sh`، `linux/services/30-vnc.sh` | XFCE + TigerVNC روی پورت 5901 برای **RealVNC Viewer** |

## سکرت‌ها و متغیرها

Settings ← Secrets and variables ← Actions. (`RUN_MINUTES` می‌تونه Variable یا Secret باشه؛ بقیه Secret.) قبل از Run بساز.

| نام | کی لازمه؟ | توضیح |
|---|---|---|
| `RUN_MINUTES` | همیشه (پیش‌فرض ۳۲۰) | طول شیفت به دقیقه؛ سقف ۳۴۰. فقط موقع شروع اجرا خونده میشه |
| `GH_TOKEN` | ماژول تحویل (توصیه‌شده) | توکن classic با scope `repo` + `workflow`؛ **مخصوص هر ریپو**، منتقل نمیشه |
| `NEXT_REPO` | تحویل به اکانت دیگه | `username/repo`؛ خالی = همین ریپو. منتقل نمیشه |
| `TS_OAUTH_SECRET` | Tailscale | `tskey-client-...` (یا `TS_AUTHKEY` / `TAILSCALE_AUTHKEY` با `tskey-auth-...`) |
| `TS_TAGS` | Tailscale با OAuth | تگی که OAuth client بهش اجازه داره (مثلاً `tag:hermes`) |
| `TS_HOSTNAME` | اختیاری | نام نود (پیش‌فرض `gh-linux`) |
| `VNC_PASSWORD` | VNC | ⚠️ فقط **۸ کاراکتر اول** اعتبار داره |
| `VNC_GEOMETRY`, `VNC_SESSION` | اختیاری | `1920x1080`، `startxfce4` |

بقیه‌ی سکرت‌هایی که برنامه‌هات لازم دارن هم به‌صورت متغیر محیطی توی `linux/*` در دسترسن. تنظیمات پیشرفته (در `env:` فایل `runner.yml`): `FG_TIMEOUT`، `END_TIMEOUT`، `GH_TIMEOUT`، `LINUX_HIDE_SECRETS` (پیش‌فرض `GH_TOKEN NEXT_REPO`؛ برنامه‌های روی لینوکس این‌ها رو نمی‌بینن).

## شیفت بین چند اکانت

| | علی | رضا |
|---|---|---|
| ریپو | ریپوی خصوصی با کل پروژه | ریپوی خصوصی **خالی** |
| دسترسی | رضا Collaborator (Write) | علی Collaborator (Write) |
| `GH_TOKEN` | توکن خود علی | توکن خود رضا |
| `NEXT_REPO` | `reza/x` | `ali/x` |
| بقیه‌ی سکرت‌ها | فقط اینجا | خودکار کپی میشن |

آخر شیفت: `linux/end` ← خاموشی سرویس‌ها ← `linux/final` (بکاپ) ← `github/post` (تحویل: آخرین نسخه‌ی ریپو + بکاپ به ریپوی بعدی، انتقال سکرت‌ها، hookهای `handoff/`، استارت workflow بعدی).
ریپوی مقصد با هر تحویل بازنویسی میشه (تاریخچه پاک)، پس تغییرات رو روی ریپوی **فعال** بده.

## نصب برنامه‌ی جدید

- **دستی** (SSH/VNC) نصب کن: پکیج‌های apt (حتی `.deb` و ریپوی سوم‌شخص) و فایل‌های `/home`، `/opt`، `/usr/local` خودکار ثبت و منتقل میشن.
- برای **سرویس**: یک فایل توی `linux/services/` (پروسه‌ها منتقل نمیشن). برای کار «هر شیفت حتماً»: فایل idempotent توی `linux/start/`.
- **منتقل نمیشه**: پروسه‌های در حال اجرا، ویرایش دستی `/etc`، ایمیج‌های داکر، snap/flatpak. برنامه‌ی حجیم رو به `overlay.exclude` اضافه و نصبش رو در `linux/start/` بنویس.
- `announce "عنوان" "متن"` (یا `cmd | announce "عنوان"`) اطلاعات رو روی «برد اطلاعات» لاگ میذاره؛ بعد از تموم شدن نصب‌ها و هر ۱۰ دقیقه چاپ میشه. رمز/توکن نفرست.
- فایل جدید باید **داخل ریپوی گیت‌هاب** باشه (از سایت: Add file)؛ `linux/start` فقط اول شیفت خونده میشه.

## تغییر دادن ریپوی بعدی

- `next-repo/` (داخل ریپو) و `~/next-repo/` (روی ماشین): هرچی توشه (با ساختار مثل ریپو) **یک‌بار** موقع تحویل اعمال و خالی میشه. حذف فایل: `next-repo/.delete`.
- `handoff-set secret|var NAME مقدار`: ست کردن Secret/Variable جدید روی ریپوی بعدی (یک‌بار؛ مقدار commit نمیشه).
- `handoff/*.sh`: hook با `gh` (هر تحویل)، `handoff/*.once.sh`: فقط یک‌بار. جزئیات: `handoff/README.md`.
- سکرت‌هایی که از اول توی ریپو بودن خودکار منتقل میشن (به‌جز `GH_TOKEN` و `NEXT_REPO`)؛ Variableها نه.

## کنترل از سایت گیت‌هاب

| کار | چطور |
|---|---|
| شروع | Actions ← Linux Runner ← Run workflow |
| تحویل همین الان | فایل خالی `HANDOFF_NOW` توی ریپوی فعال |
| توقف با ذخیره، بدون اجرای بعدی | فایل `STOP` (قبل از اجرای بعدی پاکش کن) |
| لغو فوری | Cancel — ⚠️ بکاپ گرفته نمیشه و `linux/end`، `final` اجرا نمیشن |

## محدودیت‌ها و امنیت

- ریپوها باید **Private** باشن: بکاپ شامل کل هوم (توکن‌ها، `~/.ssh`، تنظیمات) هست و به اکانت بعدی میره.
- تحویل به اکانت دیگه بدون `GH_TOKEN` و `NEXT_REPO` ممکن نیست؛ اجرای دوباره روی همون ریپو بدون توکن شخصی هم کار می‌کنه (ولی تاریخچه‌ی ریپو بزرگ میشه).
- شیفت کمتر از ۱۰ دقیقه زنجیره رو قطع می‌کنه (محافظ حلقه‌ی کرش).
- هر job گیت‌هاب حداکثر ۶ ساعته؛ ساعت ماهانه‌ی Actions برای ریپوهای خصوصی محدوده.
