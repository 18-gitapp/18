# linux/ — دستورهای خود لینوکس (مثل چیزی که با SSH می‌زنی)

همه با کاربر `runner` اجرا میشن (با `sudo` بدون رمز = دسترسی root). هر پوشه فقط `*.sh` رو اجرا می‌کنه، به ترتیب نام.

| پوشه | کی؟ | رفتار |
|---|---|---|
| `start/` | اول شیفت | یکی‌یکی اجرا میشن؛ تا تموم نشه بعدی شروع نمیشه (نصب، تنظیم، ریستور). خطا مانع بقیه نمیشه |
| `services/` | بعد از start | هر فایل یک سرویس **دائمی** در پس‌زمینه‌ست. کرش کنه ری‌استارت میشه (با تأخیر ۵، ۱۰، ۲۰... تا ۳۰۰ ثانیه). با exit 0 یعنی «تموم شد» و ری‌استارت نمیشه |
| `end/` | آخر شیفت، **سرویس‌ها هنوز روشن‌اند** | برای کارهایی مثل export دیتابیس (حداکثر `END_TIMEOUT` ثانیه هر کدوم) |
| `final/` | بعد از خاموش شدن سرویس‌ها | جای مناسب بکاپ (فایل‌ها دیگه در حال تغییر نیستن) |

- همه‌ی Secretهای ریپو متغیر محیطی‌ان (به‌جز `GH_TOKEN` و `NEXT_REPO` که عمداً مخفی‌اند؛ `LINUX_HIDE_SECRETS` در workflow).
- متغیرهای آماده: `REPO_ROOT`، `DATA_DIR` (= `~/data`)، `LOG_DIR`.
- اسکریپت‌ها هر شیفت روی ماشین تازه اجرا میشن؛ **idempotent بنویس** (`command -v x || install`، ...).
- `announce "عنوان" "متن"` اطلاعات رو روی «برد اطلاعات» میذاره (بعد از تموم شدن نصب‌ها چاپ میشه).
- فایل‌های `*.example` اجرا نمیشن؛ پسوند رو بردار تا فعال بشن.

ماژول‌های آماده (با حذف فایلشون خاموش میشن):
`start/00-baseline` + `start/10-restore` (بازیابی ماشین)، `final/50-backup` (بکاپ ۴۰MB)،
`start/05-handoff-set`، Tailscale (`start/30-tailscale`، `final/90-tailscale-logout`)، دسکتاپ + VNC (`start/40-desktop`، `services/30-vnc`).
