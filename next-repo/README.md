# next-repo — صندوق تغییرات برای اکانت بعدی

هرچی اینجا بذاری **فقط یک‌بار**، موقع تحویل شیفت روی ریپوی اکانت بعدی اعمال میشه و بعدش این پوشه خالی میشه
(پس دفعه‌ی بعد دوباره اعمال نمیشه و کارهای خود دوستت رو بازنویسی نمی‌کنه).

ساختار داخلش **مثل ریپو** است؛ مسیر فایل همون مسیر نهایی‌شه:

```
next-repo/linux/start/50-myapp.sh   →  linux/start/50-myapp.sh   (روی ریپوی بعدی)
next-repo/handoff/20-vars.sh        →  handoff/20-vars.sh
next-repo/backup.paths              →  backup.paths           (جایگزین فایل قبلی میشه)
```

**حذف فایل:** مسیرش رو (یک خط، نسبت به ریشه‌ی ریپو) توی `next-repo/.delete` بنویس. مثلاً `linux/start/50-myapp.sh`.

## دو جا برای استفاده

1. **از سایت گیت‌هاب** (توی ریپوی فعال): Add file ← Create new file ← `next-repo/linux/start/50-myapp.sh`.
2. **از روی خود ماشین** (بدون commit و push): همین ساختار رو توی `~/next-repo/` بساز.
   مثلاً `mkdir -p ~/next-repo/linux/start && nano ~/next-repo/linux/start/50-myapp.sh`.
   اگه هر دو جا فایل هم‌نام باشه، نسخه‌ی روی ماشین برنده است.

## نکته‌ها
- فقط روی **تحویل بعدی** اعمال میشه، نه همین شیفت. (همین شیفت می‌خوای؟ دستی اجراش کن.)
- هرچی یه‌بار روی ریپوی بعدی نشست، همراه ریپو به نفرات بعدی هم میره.
- Secret/Variable اینجا نذار (commit میشه). برای اون‌ها: `handoff-set` یا فایل `*.once.sh` در `handoff/`.
- مسیرهای خطرناک (`..`، `.git`) رد میشن.
